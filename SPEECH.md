## How to use this document

The speech is written as **short lines, one idea per line**. Do not memorise it word
for word. Memorise the **order of the ideas**. The words will come.

| Symbol | Meaning |
| --- | --- |
| **▶ CLICK** | press the right arrow — the slide advances one step |
| *(pause)* | stop talking for one second. It is not silence, it is punctuation. |
| ⏱ | a line you can **cut** if you are running late |
| 🛟 | your safety net — if you lose your words, say **this one sentence** and move on |

**Total spoken text: ~1 480 words ≈ 12 minutes 30.**
That leaves you 2 to 3 minutes for hesitation, breathing, and improvisation.

### The three rules that save you

1. **Speak slowly.** Slower than feels natural. Your English is judged on
   *clarity*, never on speed.
2. **If you lose a word, do not go back.** Use the 🛟 line for that slide and
   move to the next one. Nobody in the room knows what you planned to say.
3. **Every slide has one job.** If you remember only the job, you can improvise
   the rest. The jobs are: *context, pain, idea, proof, trust.*

# Q&A — prepare these ten

Short answers. Never defend — **explain**. If you do not know, say
*"I did not test that. My honest answer is…"* A jury respects that far more
than an invented answer.

**1. Why not simply use ChatGPT for everything?**
> Three reasons. Cost — it must work without a paid API. Privacy — factory data
> should not leave the company. And most important: a language model **invents**.
> My action plan must come from real past issues. So retrieval does the work, and
> the AI only writes the text.

**2. Your test data is mostly generated. Are the results meaningful?**
> For the absolute numbers — not yet, and I say so in the report. For the
> comparison — yes. Both engines were tested on exactly the same data, with the
> same questions. So the difference between minus fourteen percent and minus zero
> point two is a fair comparison.

**3. Sixty percent precision is not very high.**
> It is a strict measure. I count a result as correct only if it shares **both**
> the same root cause **and** the same solution. A genuinely useful issue that was
> fixed a different way counts as an error in my numbers. So the real usefulness
> is higher than sixty percent.

**4. Why is the threshold at 0.45?**
> It is a recall-oriented default: I prefer to show a little more, because the
> interface shows the score and the reason for each match, so the user can judge.
> I measured the alternative — around 0.55 to 0.60 gives more precision and less
> recall. It is a setting, not code, so each deployment can choose.

**5. Does it replace the expert?**
> No. It never decides. It proposes what worked before, and says where it comes
> from. The manager stays responsible. That was a design rule from the beginning.

**6. What if the problem is completely new?**
> Then nothing passes the threshold, and it returns an empty list. That is a
> deliberate choice. I prefer to return nothing than to force a bad match and
> lose the user's trust.

**7. Will it still be fast with one million issues?**
> Today it compares the query with every issue, so the time grows with the data.
> It is comfortable up to roughly ten to a hundred thousand issues. Above that,
> we bring back an approximate index — but this time we measure its recall first.
> That is exactly the lesson from my index problem.

**8. Why did you choose the weights by hand instead of learning them?**
> Because my corpus is partly generated. If I learned the weights from it, I would
> learn the habits of my data generator, not the judgement of a Lean expert. So
> the weights come from Lean practice, they are configuration, and the report
> gives the procedure to re-tune them on real data.

**9. Does it work in French, or other languages?**
> The current model is trained mainly on English. There is a multilingual model
> with the same size and the same vector dimension, so switching is a
> configuration change, not a rewrite. I did not measure it, so I cannot promise
> the quality yet.

**10. Does any factory data leave the company?**
> No. The default model runs locally, offline, with no API key. That was a
> requirement from iObeya, and the whole core feature respects it.
